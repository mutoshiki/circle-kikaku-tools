# Phase A/B independent review evidence — 2026-09-30

Scope: Phase A design contracts and Phase B shell / navigation / page anatomy. Base: `carbon-redesign` at `1c1d707fac6169218654dcc1508ed07688e65425`. This is not Phase C feature-workflow migration or production acceptance.

## Product evidence and decisions

The user supplied the real operating flow: choose participants → make/manual-adjust/randomize car/team allocation → announce it on the morning → obtain distance/costs before/during/after the event → each driver inputs their car → settle and check collections/payouts. Completion ends the principal use of this tool. The user also clarified that Overview and History are acceptable but not important primary tasks.

The revised product contract therefore separates frequent work from optional context/recovery. Published main links are Participants, Cars, Teams, Settlement; Overview and History are a separate supporting list. Room-only links now start Participants; explicit Overview and every other task link are preserved. Vehicle Costs receives its direct workspace in Phase F, not an empty Phase B navigation placeholder. No capability is deleted because it is absent from the operating narrative.

Actual defects: current mobile destination reselection left focus in an inert link; Tab exit left the drawer open; utility and drawer could overlap; scrim dismissal did not restore trigger focus. Document defects: mandatory one-Primary contradicted read pages; Apply was ambiguously required to remain open; overview/history prominence and grouped allocation lacked user-task evidence. Header metadata/action DOM order and owner-scoped mobile geometry were corrected.

Visual inspection additionally found undefined Shell typography variables: h1 and description both computed to 16px. A failing rendered hierarchy test reproduced this before repair. The Shell now uses installed Carbon's public Sass type-style API, not synthetic typography variables; feature-internal styles are not rewritten in this review.

Retained: native Carbon keyboard behavior, URL-owned section state, direct/legacy links, Grid, landmarks, g10/g100, existing feature content and all domain/persistence/sync/calculation owners. A suspected WebKit Tab-entry defect was a pointer-versus-keyboard test assumption; keyboard focus + Enter + Tab passes without a custom keyboard handler.

## Limits and next phase

This is rendered interaction, semantics and geometry coverage plus visual inspection, not a complete WCAG certification. A physical phone keyboard, real notch/safe-area, assistive-technology speech and NVDA were not tested in this review. Reduced viewport is not proof of actual software-keyboard behavior; real-device and screen-reader checks remain phase gates.

Long import/history/settings/expense/route dialogs and feature feedback remain classified migrations for C–H, not approved final patterns. Phase C must build shared surface/save/focus/feedback contracts using Product UI v1.1. The prior Phase C six commits are preserved on `codex/phase-c-shared-workflow-contracts`, not mixed into this re-audit or taken as design approval. Reconcile that branch with the reviewed foundation before resuming it. History/Overview must not become mandatory workflow stages or attract new dashboard work.

This review PR targets only `carbon-redesign`. CI and integration results are recorded in the PR; local successes above are not presented as remote CI results.
