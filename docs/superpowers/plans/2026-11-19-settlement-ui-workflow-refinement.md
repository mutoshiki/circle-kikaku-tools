# 精算画面全体のUI改善 実装計画

> **実装担当へ** `superpowers:executing-plans` でタスク順に進め、証拠を確認できた項目にチェックを付ける。

**目的** — スマホで、参加者からいくら集めるか、誰からの集金が残っているか、各車へいくら支払うかをすぐ確認できるようにする。費用入力と設定変更では、入力状況と金額への影響が分かるようにする。

**構成** — 既存の精算トップ、集金モーダル、車の費用編集、精算設定を改修する。現行の計算結果・保存処理・ナビゲーションを使い、表示に必要な判定と設定プレビューをReact側に置く。

**技術** — React、既存のCarbon React、SCSS、Playwright、Node test。

**要件の出典** — ユーザーが指定した精算UI改善案の全5節。下表のS01〜S15を全件対象とし、優先度で省略しない。コード確認基準は作業ツリーの `14ea308a`。実装開始時に `origin/main` と配信中のmanifestを再確認する。

## 実装全体の条件

- `apps/react/AGENTS.md`、`apps/react/migration/progress.json`、`docs/development/verification-and-release.md` を先に読む。既存のPR・公開版を確認し、今回の対象外の作業差分をそのまま保つ。
- 金額の情報源は既存の `calculateSettlement`。車の見出しには `adjustedTotalPay`、財源には `adjustedSplitPay` と `adjustedClubPay` を使う。表示文字列を再計算に使わない。表示に必要な新規保存フィールドは設けない。
- 通常精算はチェック操作で集金を記録し、人数だけで精算する場合は現行条件に従って「集金した人」の入力を出す。運転手の差し引き、集金記録、既存の費用データ、手動距離入力を保つ。
- 作業開始時に導入済みCarbonのButton・AccordionItem・ContentSwitcher・ModalのDOMとpropsを確認。既存のCarbonトークンと開閉・フォーカスの契約に従う。
- タスクごとに対象の既存テストへ合格条件を追加し、期待する差分で失敗することを確認してから実装する。各タスクの修正と対象テストを確認したら次へ進む。

## レビューで重点的に確認する条件

1. 保存された費用がない車に協力代や集金分の差し引きがある場合、既存の調整後金額を見落とさない。
2. 部費と集金分が相殺して合計が0円の場合、各財源の符号と明細を読める。
3. 費用編集中に別の端末が更新した場合、既存の競合処理が動き、未保存の値や成功通知を確定済みとして扱わない。
4. 設定モーダルを開いた後に別の端末で費用や集金記録が更新されても、設定の試算と保存結果が一致する。
5. 320px幅やタブ非表示の場合も、車割・費用編集・内訳の正しい入口へ進める。

## Task 1 — 費用の表示状態を決める（S03・S08）

- [x] `settlement-presentation.test.mjs` に、空欄・空白・明示的な `0`・燃費0・数値以外・複数条件不足・タイムズ距離だけ・空の追加行・金額だけ0の費用を追加する。ガソリン代は距離と単価が0でも、燃費が正で全欄が埋まれば計算済み¥0。
- [x] `getMovementInputStatus(car, settlement)` を `presentation.js` に作る。既存の条件定義・数値検証を移し、`{ kind: 'missing' | 'invalid' | 'ready', fields, errors, missingFields }` を返す。不正値と空欄が同時なら不正値を先に案内する。`fields` と `missingFields` はフィールドの `key` と `label` を持つ。
- [x] `getVehicleExpenseStatus(car, settlement)` は移動費の状態と、入力済みの明細・入力途中の明細の有無を返す。手入力明細は保存された費用名と有効な金額が揃えば入力済みとし、0も有効。未着手の空行や `pending` の仮行、自動生成される協力代・移動料金行は手入力済みの判定から外す。タイムズ時間料金は既存ラベルで金額の有無を判定。
- [x] 自家用車の移動費は任意入力のまま扱う。他の有効な明細がある場合、距離・燃費・単価がすべて空なら「ガソリン代 未入力」を費用一覧に表示し、トップは一律に要対応とはしない。距離・燃費・単価のどれかに入力があれば不足をトップにも表示する。タイムズの費用が入力済みで距離が空なら距離料金の未入力を案内する。

## Task 2 — 1台ずつ支払額を読める一覧にする（S01〜S04・S15）

- [x] `Settlement.jsx` は `SettlementPaymentRow` に既存計算の生の3金額とTask 1の入力状態を渡す。車名、右端の合計、車種や複数運転手、その下の財源、最後に内訳と編集の順で読む構造にする。人数だけで精算する場合の運転手名編集メニューも独立した操作にする。
- [x] 正の支払額で財源が1つの場合は「全額集金から／全額部費から」と表示し、同額を繰り返さない。負額は符号付き合計と「集金分／部費分」、0円で両財源とも0なら財源を省略。両財源の相殺で合計0円の場合には符号付きの両行を表示する。内訳の費目と調整額は引き続き確認できる。
- [x] 車に手入力済みの費用がなく、既存の調整後金額もすべて0なら、合計位置に「費用未入力」。協力代などの金額が既にあれば合計も表示する。一部入力では、計算済み金額を残し、該当する費用を入力するための短い状態表示を添える。「費用を入力」は未入力時の主な操作として強調する。
- [x] `AccordionItem` の開閉ボタンには車名を含むアクセシブル名、`aria-expanded` と `aria-controls` を維持。金額と編集ボタンは開閉の外側に置く。狭い幅では氏名を折り返し、収まらない場合に限り金額を次行の右端に移す。
- [x] 車内のラベル間は8px前後、情報と操作の間は12〜16px、車同士は24pxを目安に既存トークンを使う。車名・財源ラベル・区切り線の左端と、各金額の右端を揃える。タッチ操作は44 CSS px四方相当を確保する。
- [x] `settlement.spec.js` の車一覧・開閉・長い車名の既存ケースを更新し、混合財源¥2,900、片方だけ、負額、0円、相殺、未入力、部分入力、自動協力代のみ、レンタカー、複数運転手を確認する。

## Task 3 — 集金額・残り人数・一覧をつなぐ（S05〜S07）

- [x] モバイルの集金カードを「項目名と設定」→金額→進捗→主ボタンの順に組み直す。`payerCount > 0` のときは既存の `paidCount` と `unpaidCount` を使い、未完了と集金完了を要件表の文言で表示する。完了後も一覧から訂正でき、訂正時は残り人数に戻る。
- [x] `payerCount === 0` かつ `result.participants.length > 0` のときはカードに「全員が集金対象外です」を出し、「精算設定」を使って理由に対応できるようにする。同趣旨の既存グローバル通知はカードに集約し、企画者未指定など別の注意は保持する。通常の参加者0人・人数未設定では現行の開始導線を使う。
- [x] 一覧は既存の `unpaidPeople` から「未集金（n）」を描画。最終チェック後に0件の表示へ切り替え、選択中のフィルターへフォーカスを戻す。未集金のコピーは対象がいるときに表示し、全件表示の集金対象外の人と差し引き理由を保つ。
- [x] 途中8/10→完了10/10→記録を取り消して9/10、対象外混在、全員対象外、一覧のコピーとフォーカス、通常精算で直接記録、人数だけで精算する場合の現行モーダルをテストする。

## Task 4 — 費用編集で不足と計算結果を確認できるようにする（S08〜S11）

- [x] 費用一覧の移動費行と該当明細に、Task 1の状態に応じ「距離が未入力」「燃費・ガソリン単価が未入力」「入力内容を確認」などを表示する。操作すると該当項目の編集が開く。条件が揃えば既存の金額、明示的な0円なら¥0を表示する。
- [x] 移動費編集では、入力欄グループの直後に計算式と既存の `movementAmount` を見える形で出す。タイムズは距離と既存の計算結果を表示する。条件不足時は不足項目を出し、無効値は該当入力欄に案内する。
- [x] 現在の「Googleマップで距離を確認」と「操作方法」を距離欄に隣接させる。ガイド表示と次回省略、別タブ／アプリ遷移、チェックポイント復元を維持する。ガイドから戻ると距離欄に移り、外部タブを閉じて戻った後は既存の入力が残ることを確かめる。テストは既存のガイドとリンク先の検証方法を使う。
- [x] 追加費用の金額近くに、差し引き選択時の支払元と符号付き結果を表示する。妥当な入力に対して既存の `getSignedSettlementExtraAmount` を使い、未入力と無効値のときはプレビューを出さない。作成・編集・キャンセル・削除と元に戻す操作を維持する。
- [x] 現行の保存境界を使う。明細または移動費の「保存」で1回確定して費用一覧へ戻る。一覧の「閉じる」で元の車の入力／編集ボタンへフォーカスし、必要ならその行へスクロールする。車がなくなった場合は車一覧の見出しへ戻す。保存失敗・キャンセルで成功通知を出さず、金額が変わった場合は既存の保存後通知を活かす。
- [x] 燃費0、明示0円、120 kmの例、タイムズ、割勘・部費それぞれから差し引く200円、マップへの遷移と復元、保存失敗時の画面、短いモバイルでスクロールとフッターの操作を確認する。同じ明細の別端末更新を既存の競合テストで確認する。

## Task 6 — 精算設定の保存前に集金額の差を表示する（S12）
