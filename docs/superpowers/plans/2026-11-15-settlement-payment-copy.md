# 精算画面の金額表示と操作名の実装計画

> 実装担当は superpowers:executing-plans を使い、完了した工程を記録する。

**目的** — 参加者から集める額、車ごとの支払額、集金の進み具合を一覧から把握できるようにする。

**対象** — React精算画面。既存の Carbon コンポーネント、精算結果、集金記録から表示する。

| 箇所 | 表示 |
| --- | --- |
| 車一覧（車があるとき） | 車ごとの支払額 |
| 車ごとの金額 | 集金から ／ 部費から |
| 区分別内訳 | 集金分の内訳（¥2,200） ／ 部費分の内訳（−¥100） |
| 集金一覧を開く | 集金状況を見る |
| 集金の進捗 | 集金済み 8 / 12人 |
| 車の内訳を開く／閉じる | 支払いの内訳 ／ 内訳を閉じる |
| 空のメモ欄の操作 | 精算メモを追加 |

### 1. 車ごとの支払額

- [x] PR #150 の既存実装を起点にする。車なし、集金のみ、部費が負額の場合も確認する。「1人あたりの集金額」「精算設定」「費用を編集」、費用分類の「割勘」は既存の役割に沿って維持する。

### 2. 集金状況・内訳・メモ

- [x] `Settlement.jsx` の集金一覧ボタンを「集金状況を見る」にする。集金額と同じカードに、車一覧より先に進捗を出す。分母は集金対象人数の `result.payerCount`、分子は対象者のうち集金済みの人数を表す `result.paidCount`。通常と人数だけの精算で同じ表示を使い、集金対象が0人のときは進捗を出さない。
- [x] `SettlementPaymentRow.jsx` の閉じた内訳に「支払いの内訳」、展開中に「内訳を閉じる」を使う。読み上げ名には対象の車と表示中の操作ラベルを含める。
- [x] `Settlement.jsx` の空のメモ欄を「精算メモを追加」にする。保存・キャンセル・フォーカス復帰は既存操作を使う。

### 3. 検証と本番公開

- [ ] モバイルとデスクトップで文言、金額とボタンの折り返し、ライト／ダーク、開閉時の表示を確認する。ローカルの390px・1280pxの確認と、本番スモークの結果を記録する。
